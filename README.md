# IT Transfer

ระบบช่วยตรวจสอบการเทียบโอนสำหรับหลักสูตรเทคโนโลยีสารสนเทศ ใช้ HTML/CSS/JavaScript พร้อม Node.js และ SQLite

## เริ่มใช้งาน

ต้องใช้ Node.js 24 ขึ้นไป เปิด PowerShell ในโฟลเดอร์โปรเจกต์:

```powershell
npm ci
npm start
```

เปิด http://127.0.0.1:4174/admin.html เพื่อสร้างผู้ดูแลคนแรกด้วยอีเมลและรหัสผ่านของคุณ (อย่างน้อย 10 ตัวอักษร) แล้วเพิ่มหลักสูตร รายวิชา และคู่เทียบ นักศึกษาสมัครที่ http://127.0.0.1:4174/student.html หน้าแรก http://127.0.0.1:4174

ไม่มีบัญชีหรือหลักสูตรเริ่มต้น ข้อมูลเก็บใน `data/transfer.sqlite` และคงอยู่หลังเปิดเซิร์ฟเวอร์ใหม่ ปิดเซิร์ฟเวอร์ก่อนสำรองไฟล์นี้ ตัวอย่างหน้าแรกแยกจากข้อมูลจริง ต้องเปิดผ่าน Node server เพื่อใช้ระบบ

## ความสามารถ

- Admin เพิ่ม/แก้ไข/ลบหลักสูตร รายวิชา คู่เทียบ ค้นหาและกรอง ดาวน์โหลดแม่แบบ Excel ตรวจรายการก่อนยืนยัน และนำเข้าทั้งชุดใน transaction เดียว
- Admin นำเข้าคู่เทียบรายวิชาจากไฟล์ PDF ตารางประกาศเทียบโอน (เช่น มทร.ล้านนา / อาชีวศึกษา ปวส. เข้า ป.ตรี) โดยจับคู่รหัสวิชาต้นทางกับวิชาปลายทางซ้ายสุดอัตโนมัติ พร้อมแตกคู่เทียบคำว่า "หรือ" และแสดงตัวอย่างก่อนยืนยัน
- นักศึกษาสมัคร/เข้าสู่ระบบ เลือกปีหลักสูตร อ่าน PDF/JPG ด้วย OCR ไทย/อังกฤษ เปิดต้นฉบับ ตรวจและแก้ไขข้อมูลก่อนยืนยันการตรวจสอบ
- ผลเทียบได้ / เทียบไม่ได้ / ไม่พบข้อมูล พร้อมเหตุผล ประวัติส่วนตัว และพิมพ์ผล
- เซิร์ฟเวอร์ตรวจสิทธิ์และเจ้าของประวัติ ใช้ scrypt สำหรับรหัสผ่าน, HttpOnly session cookie, CSRF และ Origin validation

Admin และนักศึกษาใช้ session cookie แยกกัน เปิดสองฝั่งพร้อมกันในเบราว์เซอร์เดียวได้ การออกจากระบบหรือหมดอายุของฝั่งหนึ่งไม่ทำให้อีกฝั่งออกจากระบบ รีเฟรชแล้วยังคงอยู่ที่หน้าเดิม บัญชีผิดประเภทจะแสดงข้อความเตือนโดยไม่เปลี่ยนหน้า หลังอัปเดตจากคุกกี้รุ่นเดิม ต้องเข้าสู่ระบบใหม่หนึ่งครั้ง

## กติกา

จับคู่รหัสวิชาแบบตรงตัว (ตัดช่องว่างขอบและไม่แยกตัวพิมพ์เล็กใหญ่) ภายในปีหลักสูตรที่เลือก เกรดต้อง C ขึ้นไป รองรับ A+, A, B+, B, C+, C, D+, D, F เกรดต่ำกว่า C ให้ผลเทียบไม่ได้ ผ่านเกรดแต่ไม่มีคู่เทียบให้ผลไม่พบข้อมูลและรอ Admin อัปเดต ต้องกดตรวจสอบใหม่หลังข้อมูลเปลี่ยน ประวัติเดิมเก็บผล ณ เวลาที่ตรวจ

เกรดหรือรหัสที่ OCR อ่านไม่ชัดต้องแก้ไขเอง ชื่อวิชาและหน่วยกิตแสดงเพื่อการตรวจทาน กติกาจับคู่ใช้รหัสและปีหลักสูตรตาม Requirement

ใช้เฉพาะหลักสูตรเทคโนโลยีสารสนเทศ ไม่เชื่อม REGIS และไม่ใช่การอนุมัติเทียบโอนอย่างเป็นทางการ

## เอกสารและ Excel

PDF/JPG ไม่เกิน 10 MB, PDF ไม่เกิน 10 หน้า, JPG ไม่เกิน 30 ล้านพิกเซล OCR ทำในเบราว์เซอร์ด้วยโมเดลภายในโปรเจกต์ ไม่ส่งต้นฉบับไปบริการ OCR หรือเก็บต้นฉบับในฐานข้อมูล ส่งเฉพาะรายการที่ตรวจทานแล้วและผลตรวจไปเซิร์ฟเวอร์ รองรับไม่เกิน 200 วิชาต่อครั้ง OCR อาจคลาดเคลื่อนตามคุณภาพภาพและตาราง จึงมีข้อความดิบและช่องแก้ไข

Excel รองรับ .xlsx ไม่เกิน 5 MB รวมไม่เกิน 1,000 แถว ใช้แม่แบบจากหน้า Admin:

| ชีต | หัวคอลัมน์ |
| --- | --- |
| curricula | year, name |
| courses | year, code, name, credits |
| mappings | year, sourceCode, targetCode |

รหัสวิชาต้องเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า ไม่รองรับสูตร รายการเดิมอัปเดตตามปี/รหัส รายการซ้ำหรืออ้างอิงวิชาที่ไม่มีถูกปฏิเสธโดยไม่บันทึกบางส่วน

รองรับไฟล์แผนการศึกษารูปแบบ `แผนการศึกษาปี2567เทียบโอน.xlsx` ด้วย อ่านหัวตารางภาษาไทย รหัสวิชา ชื่อวิชา และจำนวนหน่วยกิต รวมชื่อที่ต่อบรรทัด ข้ามหัวตารางซ้ำ แถวรวม และสูตรในส่วนตารางว่าง แต่ปฏิเสธสูตรในช่องข้อมูลรายวิชา ตัวอย่างที่ตรวจอ่านได้ 45 รายวิชา รวม 131 หน่วยกิต

เมื่อใช้แผนการศึกษา ให้ระบุปีหลักสูตรที่จะบันทึกก่อนอ่านไฟล์ ปีรับเข้าและปีการศึกษาในแต่ละภาคเรียนอาจต่างจากปีหลักสูตร ระบบจะไม่ใช้ปีเหล่านั้นแทนโดยอัตโนมัติ ไฟล์นี้มีเฉพาะรายวิชา จึงไม่สร้างคู่เทียบจากจำนวนคนที่เทียบได้หรือจากวิชาบังคับก่อน ต้องเพิ่มรหัสวิชาต้นทางและคู่เทียบแยกต่างหาก ตรวจรายการแล้วทำเครื่องหมายยืนยันก่อนบันทึก

ปุ่มลบอยู่ข้างปุ่มแก้ไขทุกตาราง มีหน้าต่างยืนยันและแสดงชื่อรายการ ต้องลบคู่เทียบที่อ้างอิงก่อนลบรายวิชา และลบรายวิชาก่อนลบหลักสูตร ประวัติการตรวจสอบเดิมยังคงอยู่

## ตรวจสอบ

```powershell
npm run check
npm test
```

ใช้ Node syntax check และ built-in test runner ไม่มี TypeScript หรือ linter ที่กำหนดไว้ ทดสอบกติกาเกรด/ปีหลักสูตร, OCR parsing, Excel validation/rollback, สิทธิ์/ประวัติ/CSRF และ SQLite persistence

## ขอบเขต

เซิร์ฟเวอร์ผูก loopback สำหรับใช้งานในเครื่อง การให้หลายเครื่องใช้งานจริงต้องจัดเตรียม HTTPS, deployment, การสำรองข้อมูล และจัดการบัญชีเพิ่มเติม ยังไม่มีหน้ากู้รหัสผ่านหรือจัดการผู้ดูแลหลายคน Google Fonts เป็นส่วนเสริม มีฟอนต์ระบบสำรอง

Dependency audit ระหว่างพัฒนาพบ moderate 2 รายการจาก ExcelJS และ uuid ที่พ่วงมาด้วย (GHSA-w5hq-g745-h8pq) เส้นทาง ExcelJS ที่ตรวจพบใช้ uuid v4 ขณะที่ advisory ระบุ v3/v5/v6 ควรติดตาม upstream ก่อนเปิดใช้งานสาธารณะ

## โครงสร้าง

- index.html, styles.css, app.js: หน้าแนะนำและตัวอย่าง
- admin.html, student.html, portal.css, portal/: ระบบผู้ดูแล/นักศึกษา, OCR และ Excel
- server/: HTTP API, authentication และ SQLite
- matching.js, shared/: กติกาเทียบและการแปลงข้อมูล
- tests/: ชุดทดสอบอัตโนมัติ
- docs/system-plan.md: แผนและขอบเขตระบบ
